## 2. Kiến trúc theo đề (từ các slide của BTC)

Slide 12 — Component và Section:
- **Trang = các section xếp chồng. Mỗi section ghép từ component. Đổi dữ liệu, component giữ nguyên.**
- **Section**: một phần nội dung trọn vẹn của trang, mỗi section nói một ý, xếp nối tiếp từ trên xuống.
- **Component**: khối giao diện viết một lần, dùng lại nhiều nơi, đóng gói sẵn HTML + CSS + JS của riêng nó.
- Các component trong slide: `<wl-header>`, `<wl-hero>`, `<wl-card>` (dùng cho Lợi ích và Sản phẩm), `<wl-faq>`, `<wl-footer>`; ngoài ra có `<wl-page-head>`, `<wl-contact>`, `<wl-sticky-cta>`.

Slide 14 — Cấu tạo một trang (ví dụ `contact.html`):

```html
<body data-page="contact">
  <wl-header></wl-header>
  <main>
    <wl-page-head image="false"></wl-page-head>
    <wl-contact></wl-contact>
    <wl-faq limit="3"></wl-faq>
  </main>
  <wl-footer></wl-footer>
  <wl-sticky-cta></wl-sticky-cta>
  <script src="js/core.js"></script>
  <script src="js/app.js"></script>
</body>
```
Quy trình: (1) tạo file HTML mới, (2) thả các section cần dùng, (3) **không viết lại giao diện**.

Slide 15 — Cấu hình dự án:
- `css/base.css` giữ **màu và font** (biến `:root`: `--color-primary`, `--color-bg`, `--font-heading`).
- `data/brand-a.json` giữ **nội dung** (`name`, `slogan`, `cta`, `products`...).
- **"Đổi thương hiệu = đổi file dữ liệu. `core.js` tự điền tiêu đề, favicon, màu, font và nội dung."**

### "3 bản cấu hình" nghĩa là gì **[GIẢ ĐỊNH]**

Một **cấu hình = một thương hiệu**: bộ dữ liệu (JSON) + bộ màu/font, đổ vào **cùng một khung giao diện**. Ba file JSON khác nhau → mở cùng một `index.html` ra ba website trông và đọc khác nhau. Không phải chế độ sáng/tối (dark mode chỉ là điểm cộng, không thay thế được). Không phải 3 trang khác nhau.

Câu hỏi cần hỏi lại BTC: (a) 3 cấu hình có phải 3 thương hiệu khác nhau dùng chung code không; (b) có phải khác cả bố cục (thứ tự section) không hay chỉ màu/font/nội dung; (c) lúc chấm 11/10 nhóm có phải tự đổi cấu hình trực tiếp không; (d) **đề có cho phép dùng AI hỗ trợ viết code không**.

## 5. Bố cục "JIT" (linh động, dựng lúc chạy)

Người dùng muốn bố cục **linh động**: không ghi cứng section trong HTML mà **JSON mô tả danh sách section**, `core.js` đọc rồi dựng, chỉ nạp component nào được dùng. (JIT = just-in-time: làm đến đâu cần đến đó, code luôn, chỉnh giao diện trực tiếp trên trình duyệt, không vẽ UI chi tiết trước.)

> Lưu ý: slide 14 của BTC viết sẵn thẻ `<wl-*>` trong HTML. Đó vẫn là cách hợp lệ và đơn giản hơn. Cách JIT dưới đây là phương án nâng cao; có thể **bắt đầu bằng HTML tĩnh theo slide, chuyển sang JIT sau** nếu thiếu thời gian.

### Schema JSON đề xuất (`data/brand-a.json`)

  "theme": { "colorPrimary": "#1D4ED8", "colorBg": "#FFFFFF", "fontHeading": "Inter" },
  "menu": [
    { "label": "Khóa học", "href": "products.html", "children": [{ "label": "Web Frontend", "href": "#" }] },
    { "label": "Liên hệ", "href": "contact.html" }

      { "type": "steps", "source": "steps" },

      { "type": "contact" },
      { "type": "footer" }
    ]
  },
  "hero": { "title": "...", "image": "..." },
  "programs": [{ "name": "...", "desc": "...", "duration": "3 tháng", "price": "...", "image": "..." }],
  "features": [{ "no": "01", "title": "...", "desc": "...", "image": "..." }],
  "steps": [{ "title": "...", "desc": "...", "image": "..." }],

- `type` chọn component; `source` chọn khóa dữ liệu; `variant`, `columns`, `limit`... tùy chỉnh hiển thị.
- Brand B muốn bỏ `steps` hoặc đổi thứ tự chỉ cần sửa mảng `pages.home`.

### `core.js` (khung)

```js
const brand = new URLSearchParams(location.search).get('brand') || 'brand-a';
const page  = document.body.dataset.page || 'home';
const data  = await (await fetch(`data/${brand}.json`)).json();

const root = document.documentElement.style;
root.setProperty('--color-primary', data.theme.colorPrimary);
root.setProperty('--color-bg', data.theme.colorBg);
root.setProperty('--font-heading', `"${data.theme.fontHeading}"`);
document.title = data.name;
// TODO: đặt favicon từ data.favicon, nạp Google Font nếu cần

const app = document.querySelector('#app');
for (const sec of data.pages[page] ?? []) {
  try {
    await import(`./components/wl-${sec.type}.js`);   // chỉ nạp component được dùng
    const el = document.createElement(`wl-${sec.type}`);
    el.config = sec;                                   // cách hiển thị
    el.data   = sec.source ? data[sec.source] : data;  // dữ liệu
    app.append(el);
  } catch (e) { console.warn('Không dựng được section', sec.type, e); }
}
```

### Quy ước component
- Mỗi component: file `js/components/wl-<tên>.js`, `class extends HTMLElement`, đăng ký bằng `customElements.define`.
- Đọc `this.config` (tùy chọn hiển thị) và `this.data` (dữ liệu). **Không tự `fetch`.** Không ghi cứng chữ/nội dung trong code.
- Dữ liệu rỗng thì không vẽ gì (không vỡ trang).
- CSS chỉ dùng biến (`var(--color-primary)`...), **không ghi cứng mã màu, cỡ chữ**.
- Lưới dùng `repeat(auto-fit, minmax(240px, 1fr))` để chịu được số thẻ thay đổi; cỡ chữ dùng `clamp()`.
- Chữ dài/ngắn, thiếu ảnh, 3 hay 6 thẻ đều không được làm vỡ giao diện (thử với cả 3 brand).
- Một section lỗi không được làm sập cả trang (try/catch trong `core.js`).
- Responsive: desktop, tablet, mobile. Có alt cho ảnh, tương phản màu đủ đọc.

### Cấu trúc thư mục

```
/index.html, products.html, contact.html ...
/css/base.css              ← biến màu, font, spacing, bo góc
/css/components.css
/js/core.js                ← load JSON, áp theme, dựng section
/js/app.js                 ← logic riêng từng trang
/js/components/wl-*.js
/data/brand-a.json, brand-b.json, brand-c.json
/assets/a|b|c/             ← ảnh, logo theo từng brand
```

**Lưu ý kỹ thuật:** `fetch()` và `import()` không chạy khi mở file bằng `file://`. Dùng Live Server (VS Code) hoặc `npx serve` khi dev; deploy bằng GitHub Pages / Netlify / Vercel (miễn phí, không cần backend).

Chọn cấu hình bằng URL `?brand=brand-b` và/hoặc nút chọn nhỏ trên trang để demo nhanh khi chấm.

- **Người 2 — Khung code & logic**: `index.html`, `core.js`, `app.js`, `wl-header` (menu thả xuống), `wl-faq` (accordion), `wl-contact` (validate phía client, hiển thị "gửi thành công", có thể `mailto:`/`localStorage`), `wl-sticky-cta`, nút chọn cấu hình, deploy.

## 8. Hướng dẫn cho Claude Code khi làm việc trong repo này

1. **Không thêm backend, framework nặng hay bước build** nếu không cần. Giữ HTML/CSS/JS thuần + web components.
2. Tuân thủ kiến trúc ở mục 2 và quy ước component ở mục 5. Không ghi cứng nội dung/màu.
3. Mỗi thay đổi nên kiểm tra với **cả 3 brand** (`?brand=brand-a|b|c`).
4. Chỉ sửa file thuộc phạm vi được giao; không đổi schema JSON hay tên component khi chưa thống nhất với cả nhóm (đây là "hợp đồng" chung).
5. Giải thích code ngắn gọn bằng tiếng Việt: người dùng là sinh viên và **phải hiểu code để trả lời giám khảo** khi chấm trực tiếp và để sửa theo góp ý ở vòng sau.
6. Khi không chắc yêu cầu của BTC, nêu ra thay vì tự quyết (xem các câu hỏi ở mục 2).
